個々の指摘は `findings` 配列の要素として、以下の項目で出力してください。

* **severity**: 上記の重大度の基準に従った `Blocker` / `Major` / `Minor` のいずれか。
* **file**: 該当ファイルパス、または章・見出し名。
* **line**: 変更後の内容における行番号。特定できない場合は省略してよい。
* **excerpt**: 指摘箇所をそのまま引用したもの（行番号のズレ防止のため必須）。
  原則 1〜3 行にとどめ、長い箇所は問題が分かる範囲だけを抜き出します。
* **message**: 問題点の核心を、具体的な観点を明記して記述したもの。
* **suggestion**: **置き換え後のテキストそのもの**（提示できる場合のみ）。その場に貼れば
  直る状態にします。文章で説明するしかない場合は短い一文にとどめ、手順や理由は message へ。
* **evidence**: 差分の外を確認して判断した場合に、根拠としたファイルをリポジトリ相対パスで
  列挙したもの（確認していない場合は省略）。**実際にツールで開いたパスだけ**を書いてください。

`excerpt` と `suggestion` は、画面でそのまま引用として表示されます。**引用に地の文を
混ぜないでください。** 「例:」のような前置き、「(以下略)」、修正の手順、この指示自体への
言及は、すべて引用の一部として表示されます。伝えたいことは message に書いてください。

**引用は JSON の文字列として正しくエスケープしてください。** バックスラッシュは `\\`、
二重引用符は `\"`、改行は `\n` です。正規表現やパス、エスケープシーケンスを含む行を
そのまま貼ると壊れた JSON になり、**レビュー結果そのものが失われます。**

指摘が無い場合は `findings` を空配列にしてください。
